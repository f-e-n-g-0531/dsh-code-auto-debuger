# 用 AI 辅助调试，而不是手写计划

AI 是 DSH 当前对话中的 Agent。它先读相关代码，再根据 Visual Studio 返回的运行状态、调用栈和源位置选择下一步。插件只提供有边界的调试操作和证据记录，不运行另一套模型，不在后台自动读源码或自行推理。

## 你需要告诉 Agent 什么

先在 VS 打开并编译可调试的解决方案，在 DSH 将会话工作目录设为工程根目录。然后描述：

- 问题、预期结果和可复现输入；
- 允许调试的解决方案、目标实例或进程；
- 是否允许启动、附加、表达式求值或终止，以及明确禁止的行为。

例如：

> 帮我定位这个解决方案中空输入导致崩溃的原因。先读输入处理相关代码。只调试当前工程，允许启动、设置断点和单步；不修改源码、不附加进程、不求值、不终止。请根据每次调试结果调整下一步，最后给出证据和仍未确认的假设。

不需要列出所有断点或单步顺序。若实例、范围或风险授权不清楚，Agent 应先询问，而不是猜测或扩大权限。

## 正常流程

1. **理解代码**：Agent 使用 DSH 现有工具读取相关源码，形成待验证的假设。读代码与调试授权是不同操作。
2. **选定目标**：发现 VS 实例，明确选择实例和工作目录内的解决方案，再 `connect`。发现实例本身不是执行许可。
3. **一次授权本轮范围**：`begin` 声明目标和风险权限，创建有边界的调试会话。后台默认预算为 **64 次操作、10 分钟**，不是预先写好的 64 步计划，也不会启动后台 AI。
4. **动作 → 证据 → 决策**：每次 `perform` 只做一个原子动作。Agent 取得并检查该次完整证据后，再决定继续观察、单步、换断点、结束或询问你。不得在未读结果时盲发后续动作。
5. **交付结论**：说明观察到了什么、支持哪个判断、哪些仍未验证。调试动作成功不等于问题已解决；修复源码是另外的任务，不隐含在调试授权中。

### Agent 工具约定

以下是工具参数说明，不要求用户编写 JSON 或在面板输入计划：

- `begin`：`{ goal, confirmed: true, allowEvaluation?, allowTerminate?, allowAttach?, processId? }`。`goal` 说明本轮目标；`confirmed` 只声明已有授权，不会凭空取得用户许可。风险开关必须与用户允许的范围一致。
- `perform`：`{ investigationId, requestId, action, params }`。使用本轮返回的 `investigationId`，为该动作提供唯一 `requestId`，取得证据后再决策。标识只追踪已接受执行的原请求，不是重发未知操作的许可；动作在产生任务前被拒绝时，同一标识可以更正后重试。单个存活调查最多保留 1024 个已接受请求。
- 面板只观察本轮状态与证据、接管或取消，不负责调用 `begin` / `perform`，也不要求用户手写固定计划。

## 三类风险必须说清楚

| 操作 | 授权边界 |
| --- | --- |
| 附加进程 | 必须明确允许附加，并固定 `processId`（PID）；不得用同名进程或重启后的新 PID 替代。 |
| 表达式求值 | 可能调用函数、属性访问器或其他目标代码，不保证只读；需要明确允许求值及其风险。普通快照不等于授权求值。 |
| 终止程序 | 必须另外明确授权 `allowTerminate`；允许启动、暂停、取消或接管均不意味着允许终止。 |

后端根据 DSH 会话和规范化工作目录确定 owner，不能信任模型自填身份。权限、目标和预算在每次控制时校验；新的范围或风险必须重新确认，不得因先前授权而自行扩展。

## 观察、接管和异常恢复

- 面板用于查看状态和证据；需要亲自操作 VS 时先接管，停止后续自动控制。
- **接管和取消都不 kill 或 pause 调试目标**，不撤销已执行操作，也不证明在途操作已停止。需要暂停或终止时必须使用对应的明确操作和授权。
- 刷新、断线或超时后先查原请求及证据，再检查 VS 实际状态。结果为 `unknown` 时不得重发，不得改用旧 `execute` 绕过，也不得把重新连接当成重试许可。
- 保存失败、证据截断和缺页都必须披露；恢复观察不代表恢复执行，也不能把缺失证据写成成功。

## 兼容与验收状态

旧 `preview` / `execute` 保留给已有固定计划调用，仍受匹配预览、owner、过期和风险校验约束，不是本流程的主入口。旧计划的预算不能套用为动态会话默认值。

本流程随 **0.1.5** 发布。历史 C++ fixture 和旧 preview/execute 测试不能证明新的 AI 对话闭环、接管或真实 DSH GUI 已通过。验收要求见[测试说明](testing.md)，完整边界见[安全说明](security.md)。
