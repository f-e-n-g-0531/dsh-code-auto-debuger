# Windows EXE 性能分析

「性能分析」独立于「自动调试」。它不连接 Visual Studio，不注入、不暂停目标，也不调用 WPR 或 WPA。Windows x64 自包含助手使用 Windows ETW 与 Microsoft TraceEvent。录制内核 CPU 样本需管理员权限；无此权限可以直接导入 ETL。

## 使用

1. 在 DSH 打开工作区并选择「性能分析」。从自动加载的运行进程列表中选择目标（搜索框留空时显示全部可录制进程，输入名称片段或 PID 即时筛选，也可刷新），点击「录制并分析」（默认 7 秒，可改为 5–15 秒）。已有记录时可直接点「重新录制并分析」，新录制成功后替换当前记录，录制失败则保留。录制完成立即显示目标进程的热点：默认分析 Present 次数最多的交换链里最慢的间隔；没有可用 Present 时间线时分析整个进程录制区间。
2. 点选另一个 Present 间隔即可自动换到该区间的热点。也可输入相对 ETL 起点的毫秒范围，再点击「分析此区间」。Present 间隔并非游戏逻辑帧，也不是屏幕实际显示时长。
3. 「符号、导入与记录管理」可填写本地盘符绝对 PDB 目录（例如 `D:\Symbols\Soul`）或工作区相对目录，并导入不超过 1 GiB 的 `.etl`。不接受网络路径或联接点；在目录及其子目录中查找 EXE 或 DLL 的原生 PDB（跳过联接点和符号链接）；分析使用 ETL 中的 GUID/age 验证匹配，缺失时显示模块加偏移，不访问符号服务器。导入多个进程时先选进程，选中后即分析。
4. 录制成功会自动保存，也可点击「保存为全局默认」手动保存进程搜索词、录制秒数和 PDB 目录，跨会话使用；不会保存目标 PID、录制或 ETL 路径。
5. 热点按线程显示。创建时间支持时会标记并优先选中推定主线程；证据不足时不会用最忙线程冒充主线程。函数默认按含子调用的 CPU 时间降序，可切换为自身 CPU 时间降序。代表调用栈按样本权重排序，栈内保留调用顺序。自身统计采样指令所在函数，含子调用按样本内函数去重；CPU 时间为估算，不代表墙钟时间、单次调用耗时、等待或 GPU 耗时。一份当前记录保存在本机，热加载或重启后在原会话、原工作区打开性能分析时自动恢复，也可手动点击「恢复本会话记录」；关闭记录会清理插件采集的 ETL，但不会修改或删除导入的原文件。旧版本未保存索引的 ETL 可手动导入。

## 开发和验证

在 Windows x64 上使用 Node.js 22 与 .NET 8 SDK，运行 `npm run build:profiler`（可通过 `DSH_DOTNET` 指定 SDK），再运行 `npm run check`。生成的性能助手不需要另装 .NET 或 Visual Studio。原有 VS 调试功能继续使用自己的桥接组件。

- Soul.exe（PID 21292）：请求录制 7 秒，ETL 约 7.62 秒，0 个已报告丢失事件，单交换链 69 次 Present、5,462 个 CPU 样本，其中 5,461 个有调用栈。最慢 Present 间隔约 154.50 ms，含 74 个 CPU 样本且均有调用栈。未提供匹配的 Soul PDB，显示模块+偏移。
- 原生符号夹具：成功加载匹配 PDB，`ProfileFixtureHotFunction` 获得 191 个自身样本（总计 198 个）。VS 仅用来编译夹具，录制时未附加调试器。
